\chapter{Introduction}
\label{ch:intro}

\section{Background}
\label{sec:intro-background}

Large language models such as GPT-3~\cite{brown2020gpt3} and LLaMA~\cite{touvron2023llama} can write long passages of fluent text, and story writing is one of their most popular uses. They are built on the transformer architecture~\cite{vaswani2017attention}, which lets the model relate words that are far apart in a text, and they are trained on very large text collections~\cite{zhao2023llmsurvey}. Earlier neural story generators could stay on topic for only a few sentences~\cite{fan2018hierarchical}; current models can keep a plot going for several pages.

The usual way of using such a model is still a single request. The user types a prompt, for example ``write a fantasy story about a girl and a dragon'', and receives a finished story. All decisions about characters, setting and tone either have to be written into that one prompt or are left to the model, and once the story is written the user can only accept it or start again. Many users also find it hard to describe what they want in one go; they notice their preferences only after reading a first draft.

A question-and-answer approach changes this. The system asks the user a few short questions (where the story takes place, who the main character is, what kind of conflict and ending they want) and uses the answers to write the opening. After each chapter the user picks the direction of the next one. The user does not need to know how to write a good prompt, and the story follows their choices from start to end.

Two recent developments make it possible to run such a system on an ordinary computer. Open-weight models such as Llama 3.2~\cite{meta2024llama32} are small enough to run on a laptop, and low-rank adaptation (LoRA)~\cite{hu2022lora} and its quantised form QLoRA~\cite{dettmers2023qlora} allow such a model to be trained for a specific task by changing only a small part of its weights. This work uses both: the story model is a Llama model fine-tuned for the questions and prompts of this system, and it runs locally.

\section{Problem Statement}
\label{sec:intro-problem}

Current story generators work from one prompt, use general-purpose models that are not trained for the way an application asks for stories, and give the user little control once writing has started. A general model also tends to add titles, comments and formatting that the application then has to remove, and it has a limited context window, so earlier details of a long story can be lost.

The problem addressed in this dissertation is to design and implement a system that collects a user's story preferences through structured questions, uses a language model fine-tuned for this purpose and running locally to turn the answers into a coherent multi-chapter story, and lets the user steer the story after every chapter.

\section{Objectives of the Study}
\label{sec:intro-objectives}

The objectives of this work are:

\begin{enumerate}
    \item To design a question protocol of 17 questions on setting, character, theme and plot, with budgets of 4, 8, 12 and 17 questions, custom answers and user-added questions, and to turn the answers into structured prompts.
    \item To build a dataset in the system's own prompt format, fine-tune an open-weight Llama model on it with low-rank adaptation, and run the model locally.
    \item To generate coherent multi-chapter stories through a five-phase story-flow model, with a scene illustration, narration and genre-matched music for each chapter.
    \item To compare the fine-tuned model with the original model on stories not used in training, and to evaluate the system with users.
\end{enumerate}

The work is limited to English fiction of short to medium length (two to six chapters of 250 to 400 words), written by one user per session. Video, collaborative writing and other languages are outside its scope.

\section{Significance of the Study}
\label{sec:intro-significance}

The study shows that the language model of an interactive storytelling system can be fine-tuned and run on a laptop with 8\,GB of memory. Story text is generated without a network connection, and the user's answers are not sent to any outside service. Narration and music also run in the browser; only the scene illustrations use an online image service.

It also describes a simple way to prepare training data for an application that builds its own prompts: public stories are labelled with answers to the application's questions and passed through the application's prompt code, so the model is trained on exactly the prompts it will receive. Finally, the \texttt{custom\_elements} context channel lets users add their own questions, and the answers reach the model's prompt without any change to the code or the database.
