\chapter{Literature Review}
\label{ch:litreview}

\section{Introduction}
\label{sec:lit-intro}

This chapter covers the work on which the proposed system builds. It starts with a short overview of automatic story generation, explains the main ideas used later in the report (transformer language models, low-rank fine-tuning, local inference, prompting, and image and speech synthesis), reviews earlier story generation systems and writing tools, and ends with the research gaps that this dissertation addresses.

\section{Overview of the Topic}
\label{sec:lit-overview}

Neural story generation became practical with sequence-to-sequence models trained on large story collections. Fan et al.~\cite{fan2018hierarchical} collected about 300,000 prompt and story pairs from an online writing forum and generated a story in two steps, first a short premise and then the story conditioned on it. Yao et al.~\cite{yao2019planwrite} first produced a storyline of key words from a title and then wrote the story from the storyline. These models produced locally fluent text, but they lost track of characters and events after a few sentences.

Large pretrained transformers improved this considerably. GPT-3~\cite{brown2020gpt3} could write a convincing story from a short instruction, and later open models such as LLaMA~\cite{touvron2023llama} made similar models available for local use. Instruction tuning~\cite{ouyang2022rlhf} made models follow requests such as ``write the opening of a mystery story in about 300 words'' much more reliably. The main open problems are now control over the story, coherence over many pages, and how the user takes part in writing it~\cite{zhao2023llmsurvey}.

\section{Theoretical Framework}
\label{sec:lit-theory}

\subsection{Narrative Structure}

A common way to describe the shape of a plot is Freytag's pyramid, which divides a story into five parts: exposition, rising action, climax, falling action and resolution. The proposed system uses these five parts as the phases of its story-flow model, so that a generated story moves towards a turning point and an ending instead of continuing without direction.

\subsection{Transformer Language Models}

A transformer maps a sequence of tokens to a sequence of vectors through layers of self-attention and feed-forward networks~\cite{vaswani2017attention}. In self-attention each token forms a query $Q$, a key $K$ and a value $V$, and the output is
\begin{equation}
\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V ,
\label{eq:attention}
\end{equation}
where $d_k$ is the size of the key vectors. The matrices that compute $Q$, $K$ and $V$ and the one that projects the result back are called the query, key, value and output projections. A decoder-only model such as Llama writes text one token at a time and is trained to minimise the cross-entropy of the next token,
\begin{equation}
\mathcal{L}(\theta) = -\frac{1}{N}\sum_{t=1}^{N} \log p_{\theta}\left(x_t \mid x_{<t}\right).
\label{eq:ce}
\end{equation}
The exponential of this loss is the perplexity; lower values mean that the model predicts the text better. The model can only attend to a fixed number of tokens, its context window, so a storytelling system has to decide which parts of a long story to include in each request.

\subsection{Low-Rank Fine-Tuning}

Fine-tuning continues the training of a pretrained model on data for a specific task. Updating all weights of a model with billions of parameters needs a lot of memory. Low-rank adaptation (LoRA)~\cite{hu2022lora} keeps the pretrained weight matrix $W_0 \in \mathbb{R}^{d \times k}$ fixed and learns a small correction
\begin{equation}
W = W_0 + \frac{\alpha}{r}\,BA, \qquad B \in \mathbb{R}^{d \times r},\quad A \in \mathbb{R}^{r \times k},\quad r \ll \min(d,k),
\label{eq:lora}
\end{equation}
where $r$ is the rank and $\alpha$ a scaling constant. Only $A$ and $B$ are trained, and $B$ starts at zero, so training begins from the behaviour of the original model. QLoRA~\cite{dettmers2023qlora} stores the frozen weights in 4 bits, which reduces memory enough to fine-tune a model of a few billion parameters on a single consumer device. The result is a small adapter file that is loaded together with the original weights.

\subsection{Local Inference}

Quantisation stores each weight in fewer bits, usually 4 instead of 16, and reduces the memory needed to run a model about four times. The llama.cpp project~\cite{gerganov2023llamacpp} runs such models on ordinary processors and graphics hardware using its GGUF file format, and Ollama~\cite{ollama2024} provides a local model server on top of it that can also load a LoRA adapter. MLX~\cite{hannun2023mlx} is a framework for Apple computers that supports both running and fine-tuning quantised models. Together these tools allow a model with three billion parameters to be trained and used on a laptop.

\subsection{Prompting}

A prompt is the text sent to the model to describe the task. Liu et al.~\cite{liu2023promptsurvey} survey the ways of designing prompts, such as giving the model a role, stating constraints explicitly and adding examples. The proposed system builds its prompts from fixed templates filled with the user's answers. Fine-tuning complements this: the templates define the task, and fine-tuning teaches the model to answer those particular templates well.

\subsection{Image and Speech Synthesis}

Latent diffusion models~\cite{rombach2022ldm} generate an image by removing noise step by step in a compressed space, guided by a text description; SDXL~\cite{podell2024sdxl} is a larger model of this kind. Pollinations.ai~\cite{pollinations2024api} offers access to such models through a web address, which the proposed system uses for scene illustrations. For narration, browsers provide speech synthesis through the Web Speech interface~\cite{w3c2024webspeech}, and neural models such as XTTS~\cite{casanova2024xtts} give more natural voices at a higher computing cost. Background music is taken from the royalty-free SoundHelix tracks~\cite{brichta2024soundhelix}.

\section{Previous Research}
\label{sec:lit-previous}

\subsection{Controllable and Long-Form Story Generation}

Several studies try to give the user or the system control over the plot. Tambwekar et al.~\cite{tambwekar2019reward} used reinforcement learning to steer a story generator towards a goal event chosen in advance. PlotMachines~\cite{rashkin2020plotmachines} generates a story from an outline of key phrases and keeps track of which phrases have already been used. Re3~\cite{yang2022re3} writes stories of more than two thousand words by planning a premise, drafting with repeated prompts and then revising, and DOC~\cite{yang2023doc} improves long-range coherence with a detailed hierarchical outline. Farrell and Ware~\cite{farrell2024narrative} use a large language model as a guide for a classical narrative-planning search. All of these systems take their input once, as a goal, a premise or an outline, and then write without further input from the user.

\subsection{Interactive and Co-Creative Writing Tools}

Other work places the user inside the writing process. AI Dungeon~\cite{walton2019aidungeon} lets a player type any action and has a language model continue the story. Wordcraft~\cite{yuan2022wordcraft} is a text editor in which writers ask a model to continue, rewrite or elaborate parts of their own story. TaleBrush~\cite{chung2022talebrush} lets the writer draw the rise and fall of a character's fortune as a line that the model then follows. Dramatron~\cite{mirowski2023dramatron} builds scripts from a one-line summary through characters and scenes down to dialogue, and was tested with theatre and film professionals. These tools give the user strong control, but they expect free-form writing or editing from the user, and they use general-purpose models that are not adapted to the tool.

\subsection{Multimodal Stories}

Intelligent Grimm~\cite{liu2024grimm} generates a sequence of images for a given story with a latent diffusion model and keeps the characters consistent across the images. It does not write the story or take input from the user, and it does not add narration or sound.

\section{Research Gaps}
\label{sec:lit-gaps}

The review points to five gaps that this work addresses.

\begin{enumerate}
    \item Story generators take their input once, as a prompt, a goal or an outline~\cite{fan2018hierarchical,yao2019planwrite,rashkin2020plotmachines,yang2022re3}; none collects the user's preferences through a structured set of questions.
    \item Where the user can steer the plot, the control is set before writing starts~\cite{tambwekar2019reward,yang2023doc}, or it requires the user to write and edit the text~\cite{yuan2022wordcraft,chung2022talebrush}.
    \item The interactive tools use general-purpose models with prompts alone~\cite{yuan2022wordcraft,mirowski2023dramatron}; none adapts a model to the prompts of its own application, and none runs the model on the user's machine.
    \item Story images have been studied separately from story writing~\cite{liu2024grimm}; the reviewed systems do not combine text, illustration, narration and music.
    \item None of the reviewed systems lets the user add new questions of their own and have the answers used in the story.
\end{enumerate}

\section{Summary}
\label{sec:lit-summary}

Story generation has moved from small sequence-to-sequence models to large instruction-tuned transformers, and recent work has improved control and coherence over long texts. Interactive tools let users shape a story, but they expect the user to write, and they rely on general models used through prompts. Low-rank fine-tuning and local inference now make it possible to adapt a small open model to one application and run it on a laptop. The next chapter describes a system that combines these ideas.
